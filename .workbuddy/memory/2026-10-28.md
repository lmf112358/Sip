# 2026-10-28

## 小满 Sip v1.4.5：定位并修复「预览提醒黑屏 + 整个应用点不动」

### 现象
- 点「预览提醒」→ 出现整屏纯色 `(14,36,54)`（正是 `REMINDER_BG`），没有任何内容
- 之后**所有按钮点击无反应**，只能强杀进程
- 用户怀疑是「安装后首次打开 + 历史数据残留」

### 排查手段（这套要留着复用）
- `src-tauri/src/logging.rs`：新增文件日志，写 `%LOCALAPPDATA%\com.sip.desktop\logs\sip.log`
  （release 是 `windows_subsystem = "windows"`，stderr 是黑洞，`eprintln!` 全丢，
  这是之前一直查不出问题的根本障碍）。宏 `crate::logln!` 同时落文件 + debug 打控制台。
- 三个 HTML 加内联探针：`boot href` / `RESOURCE FAIL` / `ERROR` / `REJECT` / `root children=N`
- `E:\定时活动\win_enum.py`（ctypes EnumWindows 列窗口位置/可见性）、
  `win_grab.py`（PrintWindow 抓窗口自身画面，不受遮挡）、`click_at.py`（SendInput 点坐标）、
  `shot.py`（全屏截图 + 颜色统计）、`probe*.sh`（启动→点击→截图→读日志一体化，避免多次调用时序漂移）

### 根因
`commands::preview_reminder` 是**同步 `#[tauri::command]`，跑在主线程**。
它内部直接 `WebviewWindowBuilder::build()` + `win.url()` + `win.show()`，
而 WebView2 的同步 COM 调用需要**主线程自己的消息循环**来应答 —— 主线程正卡在调用里等它，
成了自死锁：
1. 原生窗口已创建并显示 → 只剩 `background_color` 纯色板 = 用户看到的「黑屏」
2. 页面永远不加载，`[window] 预览窗已显示` 这句日志都打不出来（它在 `url()` 之后）
3. 主线程卡死 → 之后**所有**点击无响应 = 用户说的「完全不可用」
4. 也连带第二个显示器那个窗口 `loaded=false` 被看门狗销毁

对照组：`SIP_PREVIEW` 测试钩子是在 `std::thread::spawn` 里调同一个函数，就一切正常 ——
正是这个差异锁定了「线程」这个变量。

### 修复
- `preview_reminder` 把建窗整体 `std::thread::spawn`，command 立即返回
- `logging::write_line` 加锁中毒处理（`poisoned.into_inner()`）：之前一次 panic 之后
  所有日志被静默丢弃，把真正的问题藏了起来
- `watch_load` 2.5s 固定判死 → 分 1.5/2/4s 三次探（最多 7.5s），避免慢机器误杀正常窗口
- 版本 1.4.5
