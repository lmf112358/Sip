## 小满 Sip v1.4.2：修三类严重 bug（已提交 4edba78，已推送 origin/main）

### 最重要的一条（打包链路）
`src-tauri/Cargo.toml` 缺 `[features] custom-protocol = ["tauri/custom-protocol"]`。
缺了它时 `WebviewUrl::App("reminder.html?task=…")` 会被解析成
`http://localhost:1420`（devUrl）。用 `cargo build --release` 出来的 exe 一旦
没有 dev server，提醒页就完全加载不出来 → 空窗、倒计时不跑、pending 永不释放、
后续提醒全被压住。**结论：本地验证必须用 `npm run tauri:build` 或
`cargo build --release --features custom-protocol`**，别直接 cargo build。
判断方法：日志 `[window] 提醒窗 … 1.5s 后 url=…`，只有 `http://tauri.localhost/…` 才是对的。

### 调度（scheduler.rs）
- `pending` 改为**建窗成功后**在锁外登记（原来在锁内提前写，下一 tick 被
  `has_reminder()==false` 误判「窗口已消失」清空，下一条立刻盖上来）
- `pending_limit = max(提醒配置 duration, 任务动作时长, auto_close) + 40`。
  眼睛 120s / 远眺 300s 的 `unit_value` 就是动作时长，只按提醒配置算会得到 70s，
  120s 倒计时没走完就被超时回收
- 出队严格串行 `pending_ok = e.pending.is_none()`（去掉 60s 宽限）
- 关窗/完成记录写入时都刷新 `last_pop`，留 3s 静默期，避免把淡出中的窗口拽掉

### 退出（lib.rs / commands.rs）
- 死锁根因：`on_window_event`（主线程）里 `ENGINE.lock()`，与调度线程互等。
  改读 `pub static CLOSE_TO_TRAY: AtomicBool`
- `request_quit()`：destroy_all → `app.exit(0)` → 2s 后 `process::exit(0)` 兜底
- 前端此前**没有**任何调用 `quit` 命令的地方，只能靠托盘退出；已在设置页
  「关于」卡片加「退出小满」按钮（i18n: settings.quit / settings.quitConfirm）

### 关闭方式
Esc / 点击任意位置 / Alt+F4（`closable(true)`）/ `Ctrl+Shift+X` 全局逃生键；
消息窗也支持 Esc。

### 验证方式（可复用）
- `SIP_IGNORE_LOCK=1 SIP_QUIT_AFTER_SEC=N ./src-tauri/target/release/sip.exe > run.log 2>&1`
- 日志关键字：`[scheduler] 弹出提醒`、`[window] 提醒窗 … 1.5s 后 url=`、
  `[ui] reminder timer/mount/close`、`[scheduler] pending 回收`、`[watchdog]`
- `tools/shot.mjs`：无头 Chrome 打开 `dist/reminder.html?preview=1` 抓 console + 截图，
  用来单独验证前端（React app 在浏览器里走 src/lib/mock.ts）
- 注意：真机跑测试会全屏弹窗盖住用户屏幕，用户可能会点掉，导致记录出现
  「complete=unit_value」的假数据 —— 看到这种要怀疑人为点击而不是代码 bug

### 环境坑
- C 盘一度 100% 满（回收站 25G），导致 `cargo` 打包报
  `failed to build archive … 磁盘空间不足 os error 112`。
  `Clear-RecycleBin` 无效，最终用 `Remove-Item C:\$RECYCLE.BIN\<SID> -Recurse -Force` 解决
- `target/debug` 会涨到 8G+，随时可删
